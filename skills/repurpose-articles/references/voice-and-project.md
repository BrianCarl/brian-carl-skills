# User voice and project

## Personalization

Ship this reference without a preset author, website, biography, or source quotations. Learn the user's voice from their current article, explicit preferences, and writing samples. Do not treat worked hook examples as the user's actual words.

Use context already supplied in the current conversation. Ask about missing audience, destination, or goal only when the answer materially changes the output. The skill must work from a single complete article without requiring a setup interview.

## Optional local user profile

Use a completed profile only when the user has supplied or confirmed its values. Keep another user's configuration in their local copy or authorized private storage rather than contributing it to the public shared skill.

- Author: use the user or their explicitly named author.
- Source website or feed: use the supplied or established URL; leave unknown otherwise.
- Audience: use the user's specified audience; infer from the current article when unspecified and state the assumption.
- Primary goal: use the stated goal; default to article visits and newsletter subscriptions when no other goal is supplied.
- Publication/newsletter promise: use only an established cadence and benefit; never invent one.
- Voice samples: use the current article and additional user-supplied writing.
- Words or habits to preserve: retain relevant phrases and quirks from those samples.
- Words or habits to avoid: follow the user's explicit preferences.
- CTA destination and style: use a supplied or verified destination and the user's preference.
- Hook feedback: record user-selected wording as preference calibration, with its origin. Distinguish an assistant-written approved hook from the user's original prose.

## Default working preferences

- Produce an X thread and a LinkedIn post unless the user narrows the scope.
- Show three distinct hooks, recommend one, and provide finished drafts together.
- Reuse the user's own wording wherever it works.
- Draft without paid publishing dependencies or assumptions about a particular client.

## Order of authority for voice

1. Explicit current directions and user edits.
2. The current article's actual wording.
3. Additional supplied author-written posts and prose.
4. A user-confirmed local profile.
5. Generic editorial judgment.

Treat a limited sample as initial calibration rather than a comprehensive voice fingerprint. Do not impose a tone such as executive, casual, contrarian, or vulnerable on every author. Preserve chosen published wording rather than guessing which lines were AI-assisted.

Build a phrase bank from the actual source for each request. Reuse only relevant phrases and quote verbatim only when the draft retains them. Label small changes as edited source and new hooks as new framing. If the source author differs from the user, preserve attribution and never turn that author's experiences into the user's personal claims.

## Feedback

Learn the reason a user prefers a hook: concrete stakes, relevance, specificity, useful curiosity, or authentic source language. Transfer that reasoning without forcing the same formula on every article. A selected hook is not evidence of engagement or conversion performance.
